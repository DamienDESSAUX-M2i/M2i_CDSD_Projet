# 2. Pipeline Responsibilities

The `DatasetBuilderPipeline` is responsible for constructing machine learning datasets from preprocessed samples previously generated by the preprocessing pipeline.

The pipeline:

- Retrieves sample metadata from MongoDB.
- Splits samples metadata into train, validation, and test subsets.
- Loads preprocessed samples from MinIO.
- Separates features and targets.
- Optionally generates temporal context windows.
- Concatenates all samples into ML-ready datasets.
- Stores dataset metadata for reproducibility.

The resulting datasets are ready for model training and evaluation.

# 3. Pipeline Configuration

The pipeline behavior is controlled through `DatasetBuilderPipelineSettings`.

## 3.1. Dataset Selection

The following parameters control which datasets are included:

```python
datasets_used: tuple[str]
max_samples_per_dataset: int | None
preprocessing_pipeline_id: str | None
```

Example:

```python
datasets_used = (
    "GuitarSet",
    "IDMT-SMT-Guitar",
)
max_samples_per_dataset = 100
preprocessing_pipeline_id = "84a43ab1fef8b0307313f9325f487aa5303f897186b5ba1b98a7bba88656c60b"
```

The pipeline will only load a maximum of 100 samples generated by the selected preprocessing pipeline and belonging to the selected datasets. If `max_samples_per_dataset` is set to `None`, all samples will be loaded. If `preprocessing_pipeline_id` is set to `None`, the last executed preprocessing pipeline will be selected.

## 3.2. Split Strategy

The dataset split is controlled using:

```python
train_size: float
validation_size: float
test_size: float
random_state: int
shuffle: bool
```

Example:

```python
train_size = 0.7
validation_size = 0.1
test_size = 0.2
random_state = 73
shuffle = True
```

Constraints:

```text
train_size + validation_size + test_size = 1.0
train_size >= 0
validation_size >= 0
test_size >= 0
random_state >= 0
```

## 3.3. Context Window Configuration

Temporal context can optionally be added.

Parameters:

```python
use_context_window: bool
context_size: int
```

Example:

```python
use_context_window = True
context_size = 5
```

This generates a centered window for each frame:

```text
[t-5 ... t ... t+5]
```

The target remains unchanged.

# 4. Input Data Requirements

## 4.1. Sample Metadata

The pipeline first loads sample metadata from MongoDB.

Required fields include:

| Field | Description |
| :- | :- |
| dataset_name | Source dataset |
| bucket_name | MinIO bucket |
| object_name | Sample parquet file |
| preprocessing_pipeline_id | Source preprocessing pipeline |

## 4.2. Sample Files

Each sample stored in MinIO must contain features and target and stored as a parquet file.

# 5. Execution Flow

The pipeline executes the following steps:

```text
Load metadata
        ↓
Split metadata
        ↓
Load train samples
        ↓
Load validation samples
        ↓
Load test samples
        ↓
Build context windows (optional)
        ↓
Save pipeline metadata
        ↓
Save dataset metadata
        ↓
Compute statistics
        ↓
Return datasets
```

# 6. Dataset Construction

## 6.1. Feature / Target Separation

Features and targets are identified using column prefixes.

Feature prefixes:

```text
stft_
mel_
cqt_
chroma_
mfcc_
```

Target prefix:

```text
midi_pitch_
```

The pipeline automatically separates both groups.

## 6.2. Context Window Generation

When enabled, neighboring frames are concatenated around the current frame.

Example:

Input:

```text
x0
x1
x2
x3
```

With:

```python
context_size = 2
```

Output:

```text
[x0 x0 x0 x1 x2]
[x0 x0 x1 x2 x3]
[x0 x1 x2 x3 x3]
[x1 x2 x3 x3 x3]
```

Padding strategy:

```text
edge padding
```

This preserves the number of frames.

## 6.3. Dataset Concatenation

After loading all samples `pandas.concat(...)` is used to create a single dataset.

This results in two dataframes (_features, _target) per dataset (train, validation, test).

# 7. Train / Validation / Test Split

Splitting occurs at the sample level. This guarantees that sample cannot appear in multiple subsets. No frame leakage occurs across splits.

# 8. Metadata Persistence

## 8.1. Pipeline Metadata

Pipeline metadata is stored in MongoDB.

Stored information includes:

- pipeline name
- pipeline id
- pipeline version
- output dataset name
- datasets used
- the maximum number of samples per dataset
- preprocessing pipeline id
- split configuration
- context window configuration

This allows full experiment reproducibility.

## 8.2. Dataset Metadata

Dataset metadata contains:

```python
{
    "dataset_name": "my_dataset"
    "dataset_builder_pipeline_id": "9d3ab75c8f911048d0a6f62d5fe99435a39da792597da3004538ca0f8af3bb8c",
    "train_objects_names": [...],
    "train_samples": 70
    "validation_objects_names": [...],
    "validation_samples": 10
    "test_objects_names": [...],
    "test_samples": 20
}
```

This enables reconstruction of the exact dataset composition.

# 9. Statistics Collection

The pipeline tracks execution metrics through `DatasetBuilderPipelineStatistics`.

Tracked metrics include:

| Metric | Description |
| :- | :- |
| pipeline_metadata_inserted | Pipeline metadata inserted into MongoDB |
| pipeline_metadata_updated | Pipeline metadata updated in MongoDB |
| dataset_builder_error | Pipeline errors |
| sample_metadata_loaded | Metadata documents loaded |
| dataset_metadata_inserted | Dataset metadata inserted into MongoDB |
| dataset_metadata_updated | Dataset metadata updated into MongoDB |
| sample_loaded | Samples loaded from MinIO |
| dataset_loaded | Dataset loading phase completed successfully |
| dataset_size | Total dataset size |
| train_size | Number of train samples |
| validation_size | Number of validation samples |
| test_size | Number of test samples |
| train_ratio | Train percentage |
| validation_ratio | Validation percentage |
| test_ratio | Test percentage |

Metadata persistence metrics are reported at the end of the execution.

# 10. Outputs

The pipeline returns six pd.DataFrame:

```python
(
    (train_features, train_target),
    (validation_features, validation_target),
    (test_features, test_target),
)
```

All datasets are frame-aligned and ready for model training.

# 11. Reproducibility

Reproducibility is ensured through:

- versioned preprocessing pipelines
- versioned dataset builder pipelines
- MongoDB metadata persistence
- deterministic random seed
- dataset composition tracking
- train / validation / test split recording

This guarantees that a dataset can be rebuilt exactly from its metadata and associated preprocessing pipeline version.
